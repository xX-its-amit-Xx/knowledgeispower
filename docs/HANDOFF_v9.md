## 5. How to resume each run

All three driver scripts skip work whose output JSON already exists, so after a crash or reboot you just rerun them,
from the repository root, in the background:

```bash
cd /home/user/knowledgeispower
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
nohup nice -n 15 bash scripts/run_v9_holdouts.sh  >> results/v9/holdout_runs.log   2>&1 &
nohup nice -n 15 bash scripts/run_v9_addendum.sh  >> results/v9/addendum_runs.log  2>&1 &
nohup nice -n 15 bash scripts/run_v9_addendum2.sh >> results/v9/addendum2_runs.log 2>&1 &
```

- **`run_v9_holdouts.sh`** runs `benchmarks/confirm_v9.py <holdout> --jobs 3` for every holdout without
  `results/confirm_v9/<holdout>.json`, in preregistered order. `confirm_v9.py` has **no per-split cache**, so an
  interrupted holdout starts again from split 1. Each holdout is "single use": disclose any restart in the log and in
  the report.
- **`run_v9_addendum.sh`** first finishes any missing dev target, then runs `addendum_v9.py <holdout> --jobs ${JOBS:-1}`
  for every holdout that has a `confirm_v9` JSON but no `results/v9/addendum/<holdout>.json`. For holdouts still
  waiting on `confirm_v9`, it polls once a minute. Per-split results are cached in `data/cache/v9_addendum/`, so a
  restart resumes mid-holdout. It needs `PIMMS_PYTHON` (§6).
- **`run_v9_addendum2.sh`** runs `addendum2_v9.py` on the 5 primary sets (seeds 9000–9003, the 8 methods listed in the
  script), skipping sets that already have `results/v9/addendum2/<holdout>.json`. Its cache is
  `data/cache/v9_addendum2/`. It needs R (§6).
- **Before restarting after a code fix** (not just a crash), delete that holdout's cshrink score-cache entries first.
  The cache key does not hash V, warm or base (`docs/v9_review.md`, leakage, minor items).
- **Once everything has landed,** regenerate the summaries with `python scripts/summarize_v9.py` and
  `python scripts/summarize_v9_addendum.py`. These write `docs/v9_results.md` and `docs/v9_addendum_results.md`.
  Then update §3.2, §5 and §7 of `docs/v9_validation.md`.
